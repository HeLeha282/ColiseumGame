# ColiseumGame — контекст проекта

Игра делается вдвоём (репозиторий: https://github.com/HeLeha282/ColiseumGame, ветка `main`).
Общение — на русском. Платформа разработки — Windows.

## Концепция

**Жанр:** 3D action tower defense (референсы: Orcs Must Die!, Dungeon Defenders, Sanctum).
**Движок:** Unity (шаблон 3D URP).

- Действие в **Колизее**. В центре арены стоит **портал**, который игрок защищает.
- Враги появляются из арок на **верхних ярусах**, спускаются по лестницам/пандусам ярусов
  по **фиксированному запутанному маршруту** (спираль, развилки открываются на поздних волнах),
  затем идут по арене к порталу.
- Есть **летающие враги** — они пикируют сверху, игнорируя маршрут (против них лук и анти-воздушные башни).
- **Игрок** бегает сам, камера переключается **3-е лицо (как в Genshin Impact) ↔ 1-е лицо**.
  Оружие: меч, лук (дальше — ещё). Способности/прокачка персонажа — позже, не в прототипе.

### Цикл игры
1. **Фаза подготовки** (без таймера, кнопка «Готов»): ставим/прокачиваем башни, ставим баррикады.
2. **Фаза волны**: деремся сами, **чиним** повреждённые башни (только игрок, стоя рядом, за валюту),
   подбираем награду.
3. Награда за волну → снова подготовка. Каждые 5 волн — босс.

### Башни
- Ставятся в **заданные слоты** на ярусах и арене.
- Одна валюта («эссенция»): за убийства + бонус за волну.
- Прокачка: уровни 1 → 2 → 3, на 3-м выбор **ветки** (напр. «Ледяная» / «Скорострельная»).
  На максимуме — **гибридный слот** для второй ветки (ледяная + скорострельная). **Слияния башен нет.**
- Базовые типы: лучник (одиночная цель), баллиста/катапульта (AoE), жаровня (огонь), анти-воздух.

### Баррикады (РЕШЕНО)
Баррикады **не меняют маршрут**. Это разрушаемые препятствия на пути: враги останавливаются
и ломают их, пока их бьют башни и игрок.

### Баланс «руки vs башни»
Без башен выиграть нельзя, без участия игрока — очень тяжело. Рычаги:
- щитоносцы (неуязвимы спереди для башен), летающие, элитки с бронёй, которую снимает только игрок;
- «метка»: враг, ударенный игроком, получает от башен ×1.5 урона;
- ремонт башен — только игроком;
- часть валюты падает с врагов и исчезает через ~10 с, если не подобрать.

## Ещё не решено
- Визуальный стиль (кандидаты: stylized hand-painted как WoW / low-poly как Synty / мультяшный).
- Тематика врагов (вариант: античная мифология — скелеты-легионеры, сатиры, гарпии, минотавр, гидра).
- Сколько ярусов у Колизея и сколько арок-спавнов.

## Журнал разработки (ОБЯЗАТЕЛЬНО)
Работают два человека, у каждого свой Claude Code. Чтобы не делать работу дважды:
- В начале сессии: `git pull` и прочитать `DEVLOG.md` (раздел «Кто что делает» и последние записи).
  Если задача уже сделана или кто-то её взял — сказать об этом пользователю, а не переделывать.
- Беря большую задачу — вписать её в таблицу «Кто что делает» и запушить.
- После каждого завершённого шага: добавить запись **сверху** в `DEVLOG.md` (дата, кто, что сделано,
  что выбрали и почему, что осталось) и закоммитить вместе с изменениями.
- Важные решения дублировать в этот файл (концепция/правила), если они меняют проект.

## Технические правила
- Git + **Git LFS** (`.gitattributes` уже настроен на модели/текстуры/аудио). Unity `.gitignore` уже есть.
- Свой код и ассеты — только в `Assets/_Project/...`, сторонние паки — в `Assets/ThirdParty/`.
- Сцены Unity плохо мержатся: собирать всё из **префабов**, не править одну сцену одновременно вдвоём.
- Asset Serialization = Force Text. Оба разработчика на **одной версии Unity**.
- Конфиги башен/врагов/волн — через **ScriptableObject**, чтобы баланс правился без кода.
- Камера — Cinemachine. Ввод — новый Input System.

## План
0. Концепт и мини-GDD — в процессе.
1. Настройка репозитория и Unity-проекта — готово.
2. **Серый прототип** — готов (см. DEVLOG): персонаж с переключением 1-го/3-го лица, меч и лук,
   Колизей с 2 ярусами, 4 типа врагов (пеший, щитоносец, летающий, босс), 2 башни, баррикады,
   10 волн, валюта, ремонт. ← **следующий шаг: живой плейтест людьми** — «весело ли это на кубах?»
3. Вертикальный срез: выбранный стиль, первые модели (асcет-паки + ИИ: GPT-концепт → image-to-3D → Blender → Unity).
4. Контент: все башни и ветки, враги, боссы, прокачка персонажа.
5. Баланс, полировка, VFX, звук, меню, плейтесты.

## Текущее состояние
Шаг 1 выполнен: папка подключена к GitHub (`main`), Git LFS включён.
- **Unity 2022.3.10f1** (обоим разработчикам нужна именно эта версия), проект на URP 14.0.8.
- URP-ассеты: `Assets/_Project/Settings/URP_PipelineAsset.asset` + `URP_Renderer.asset`
  (назначены в Graphics и во всех уровнях Quality). Color space — Linear.
- Пакеты: URP, Input System 1.7.0 (Active Input Handling = Both), Cinemachine 2.9.5,
  ProBuilder 5.1.1 (для серой геометрии Колизея), AI Navigation 1.1.4 (NavMesh для врагов), TextMeshPro.
- Стартовая сцена: `Assets/_Project/Scenes/Prototype.unity` (в Build Settings).
- MCP для связи Claude Code с редактором: **CoplayDev/unity-mcp** (пакет `com.coplaydev.unity-mcp`,
  сервер запускается через `uvx`, конфиг в `.mcp.json`). Требует Python 3.10+ и `uv`.
  В окне Window → MCP for Unity транспорт должен быть **Stdio** (не HTTPLocal), «Configure Clients» не нажимать.

Шаг 2 (серый прототип) выполнен — играбельный цикл из 10 волн в `Prototype.unity`.
- Код: `Assets/_Project/Scripts` (сборка `ColiseumGame.asmdef`, неймспейс `ColiseumGame`), по папкам Core/Player/Enemies/Towers/Waves/UI/Combat.
- **Генератор**: меню **ColiseumGame → Build Prototype** (`Assets/_Project/Editor/PrototypeBuilder*.cs`) пересоздаёт
  материалы, все префабы и сцену + запекает NavMesh. Конфиги в `ScriptableObjects/` он создаёт только если их нет.
  ⚠ Ручные правки сцены/префабов генератор затрёт — либо правьте его код, либо перестаньте его запускать (решить вдвоём).
- Баланс: `ScriptableObjects/GameBalance.asset` (эссенция, метка, портал, баррикады, ремонт, списки башен и волн),
  `Enemies/*`, `Towers/*` (уровни 1–3), `Waves/Wave_01..10`, `Player/PlayerConfig`.
- Маршруты врагов — объекты `Routes/Route_N`, точки маршрута = дочерние объекты по порядку. После правки геометрии —
  ColiseumGame → Rebake NavMesh.
- Ввод: `Assets/_Project/Settings/ColiseumControls.inputactions`, читается через `InputReader`.
- Автотесты через MCP: `PlaytestBot` (только в редакторе) — бот-игрок, жмёт клавиши через очередь Input System.
  Для тестов без фокуса окна Game: `Application.runInBackground = true` и
  `InputSystem.settings.editorInputBehaviorInPlayMode = AllDeviceInputAlwaysGoesToGameView` (только в памяти).
